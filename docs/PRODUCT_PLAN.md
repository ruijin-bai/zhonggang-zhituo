# 中港智拓｜产品规划

> 产品名：**中港智拓 Zhonggang Zhituo**  
> 定位：**海外工程市场机会发现与战略经营智能体**  
> 核心命题：**去哪里、追什么、怎么拿。**  
> 版本：v0.1 Competition Planning

---

## 1. 为什么做智拓

海外工程市场经营的真正难点，并不是“信息少”，而是**信息太多、来源太散、质量不一，而且最终需要转化成经营判断和行动**。

市场人员日常面对的信息包括：

- 政府发展规划、预算和招标信息；
- 港口、公路、桥梁、疏浚、机场、市政、水务等项目动态；
- 世界银行、非洲开发银行、各国财政部及开发性金融机构的融资信息；
- 业主、政府部门、咨询单位、当地合作伙伴和竞争对手动态；
- 企业自身历史业绩、属地资源、专业能力与合作网络；
- 国别政治、财政、汇率、主权信用、营商环境和安全风险。

这些信息通常散落在网站、报告、邮件、Excel、PPT、聊天记录和个人经验中。

最终却必须回答非常具体的经营问题：

1. 这个国家值不值得继续投入？
2. 这个项目是不是一个真正的机会？
3. 现在是不是进入窗口？
4. 公司有没有能力和资源拿下？
5. 谁是关键业主、决策者、融资方和合作伙伴？
6. 主要竞争对手是谁？
7. 如果投入经营资源，下一步应该做什么？

智拓的目标不是“替人做决定”，而是建立一套**信息可聚合、机会可发现、判断可解释、策略可生成、过程可跟踪**的市场经营辅助体系。

# 2. 产品愿景

## 2.1 一句话定义

> **智拓是一名面向海外工程市场经营的 AI 参谋：持续发现机会、判断机会、解释机会，并形成下一步经营行动建议。**

## 2.2 长期愿景

将企业海外市场经营从：

```text
人找信息
→ 人整理材料
→ 人凭经验判断
→ 人写报告
→ 人跟踪项目
```

升级为：

```text
AI持续扫描
→ AI结构化信息
→ AI发现机会
→ 数据+规则+AI协同研判
→ 人做最终经营决策
→ AI持续监控变化
```

最终沉淀三类企业资产：

1. **市场情报资产**：国别、客户、项目、融资、竞争情报；
2. **经营知识资产**：历史项目判断、成功/失败经验、关键判断逻辑；
3. **决策规则资产**：机会评分、风险边界、关注条件、跟踪机制。

# 4. 核心业务痛点

## 痛点 P1：机会发现高度依赖人

大量项目在正式招标前数月甚至数年就已经出现规划、可研、融资、顾问招募或预算迹象。

如果企业等到正式招标才发现项目，往往已经错过最佳经营窗口。

**智拓目标：把“被动收到项目”变为“提前发现项目”。**

---

## 痛点 P2：信息搜集时间长

一个项目初步研判通常需要分别查询：

- 项目背景
- 业主
- 资金来源
- 项目阶段
- 技术规模
- 竞争对手
- 国别风险
- 企业自身业绩匹配

大量时间消耗在搜索、复制、整理和交叉验证。

**智拓目标：把“搜集信息”从主要工作变成机器工作。**

---

## 痛点 P3：项目判断依赖个人经验

不同市场人员面对同一个项目，可能因为经验不同得出完全不同的结论。

企业缺少统一、可解释、可复盘的机会判断尺度。

**智拓目标：建立标准化机会评分框架，同时允许专家修正。**

---

## 痛点 P4：大量市场精力投入低价值项目

真正昂贵的不是“漏掉一条新闻”，而是：

> 在一个胜率低、资金不明确、业主质量差或公司能力不匹配的项目上持续投入大量经营资源。

**智拓目标：帮助尽早识别“不值得追”的项目。**

---

## 痛点 P5：历史经营经验无法复用

某个国家为什么当年没有进入？某项目为什么丢标？哪个业主偏好什么合作方式？哪些合作伙伴真正可靠？

这些经验通常存在于个人脑中。

人员轮换后，经验容易流失。

**智拓目标：让每一次项目判断都成为下一次判断的数据。**

# 8. 智拓 100 分机会评分模型

这是首版产品最重要的“决策骨架”。

评分绝不能完全由 LLM 自由发挥。

采用：

```text
结构化指标 + 可配置规则 + 数据证据 + AI辅助解释
```

## 8.1 建议评分维度

| 维度 | 权重 | 核心问题 |
|---|---:|---|
| 战略匹配度 | 15 | 是否符合公司区域与业务方向 |
| 专业能力匹配 | 20 | 公司是否有对应业绩、技术和资源 |
| 项目成熟度 | 15 | 项目是否真正推进，而非概念项目 |
| 融资确定性 | 15 | 钱从哪里来，资金是否落实 |
| 业主质量 | 10 | 业主信用、决策效率、履约能力 |
| 竞争态势 | 10 | 竞争是否过度激烈，公司是否有优势 |
| 属地资源基础 | 10 | 机构、合作方、设备、团队等基础 |
| 风险调整 | 5 | 政治、安全、汇率、付款等风险 |
| **合计** | **100** | |

## 8.2 等级

```text
S  85–100   战略级机会
A  75–84    重点跟踪
B  60–74    持续观察
C  40–59    谨慎介入
D  <40      暂不投入
```

具体边界后续通过业务测试调整。

## 8.3 评分解释

输出不是简单一句：

> 综合评分 82 分。

而应该解释：

```text
综合评分 82 / 100（A · 重点跟踪）

主要加分项：
+ 公司在该区域已有项目执行基础
+ 项目专业类型与核心能力高度匹配
+ 多边融资机构已披露融资动作

主要减分项：
- 项目尚未进入正式采购阶段
- 主要国际承包商已有前期介入迹象

当前最大不确定性：
融资协议是否在未来90天内正式生效。
```

# 9. Go / No-Go 决策辅助

评分不是最终目的。

市场人员最终需要的是：**现在应该怎么办？**

智拓输出四档建议：

### GO — 建议重点投入

满足核心门槛，建议进入重点经营。

### WATCH — 持续跟踪

项目有价值，但关键条件尚未成熟。

### CAUTION — 谨慎投入

风险较高，仅进行低成本跟踪。

### NO-GO — 暂不投入

现阶段投入资源的预期价值较低。

## 必须说明

AI 输出属于**辅助决策建议**，最终经营决策由业务人员作出。

# 10. “怎么拿”——经营策略智能体

这是智拓区别于普通“项目评分工具”的关键。

项目进入重点跟踪后，AI自动生成 **Pursuit Brief**。

## 10.1 输出结构

### 项目一句话判断

> 一个值得提前介入但融资落地仍需验证的港口疏港公路机会。

### 赢标关键因素

例如：

1. 融资能力
2. 港口道路一体化业绩
3. 本地实施资源
4. 政府及业主沟通
5. 工期方案

### 竞争态势

- 可能竞争方
- 对方优势
- 公司相对优势
- 需要补足的能力

### 关键相关方

- 业主
- 政府主管部门
- 融资机构
- 顾问
- 潜在当地合作伙伴

### 下一步行动

必须输出具体行为，而非泛泛建议：

```text
1. 核实融资协议状态
2. 获取可研顾问信息
3. 调研业主近5年同类采购模式
4. 筛选2家本地道路分包资源
5. 评估现有港口项目业绩是否可作为资格业绩
```

用户可直接提问：

> 西非最近半年有哪些港口类机会值得跟？

> 这个项目为什么只有68分？

> 给我找出目前机会池里公司业绩匹配度最高的5个项目。

> 如果只允许跟3个项目，推荐哪3个？

AI 不应只做知识问答，而应调用项目库和评分数据形成分析。

# 12. 证据链与可信 AI

市场经营判断不能只输出“AI认为”。

智拓每项重要结论必须尽量提供证据。

## 证据类型

```text
政府官方信息
国际金融机构
业主公告
招标公告
可信媒体
企业内部数据（正式环境）
人工录入
AI推断
```

必须区分：

### Fact 事实

来源直接支持。

### Signal 信号

多个事实共同表明一种趋势。

### Inference 推断

AI根据已知信息给出的判断。

例如：

> **事实：** AfDB 已批准项目融资。

> **信号：** 业主近一个月连续启动顾问采购与环境评估。

> **AI研判：** 项目进入未来6个月采购准备阶段的可能性较高。

这种表达是比赛中非常重要的可信度设计。

# 13. 变化监控

市场机会不是静态档案。

项目可能每天变化。

智拓应记录：

```text
2026-08-10   项目首次发现
2026-08-16   新增：AfDB融资谈判
2026-08-21   新增：可研顾问招募
2026-08-23   机会评分 71 → 78
```

用户真正关心的是：

> **“发生了什么变化，这个变化是否影响我的经营判断？”**

首版可通过人工触发更新模拟持续监控，不必为了比赛过早建设高成本实时爬虫系统。

# 15. AI 与规则的职责边界

这是架构红线。

## AI 擅长

- 摘要
- 实体识别

- 分数计算
- 权重

- 数据状态


```text

```

# 16. 技术方案原则

技术栈以：

> **主流、稳定、开发效率高、展示效果专业、方便个人维护**

为标准，不需要为了与其他项目保持一致而限制技术选型。

## 建议技术形态

### Frontend

- Next.js / React
- TypeScript
- Tailwind CSS
- shadcn/ui
- ECharts / Recharts
- MapLibre / Leaflet

### Backend

优先两种方案二选一：

**方案 A：FastAPI + Python**

适合 AI 数据处理、评分、任务和后续分析扩展。

**方案 B：Next.js Full Stack**

适合竞赛快速交付。

综合智拓的数据分析属性，正式建议 **FastAPI + PostgreSQL + Next.js**。

### Database

- PostgreSQL

首版不建议一开始引入过多中间件。

### AI Layer

设计模型适配层：

```text
ModelProvider
├── OpenAI-compatible
├── CCCC Jiaorong Adapter
└── Mock Provider
```

非涉密研发和公开数据演示可使用主流模型；正式接入公司内部涉密场景时必须切换到合规模型与环境。

# 19. 竞赛版本的“英雄场景”

比赛不能平均展示十几个功能。

必须设计一个 3～5 分钟的主故事。

## 推荐故事

### 场景背景

市场人员每天收到大量碎片化行业信息。

### Step 1：AI发现机会

系统从一条政府 / 金融机构公开信息中识别：

> Nigeria XXX Port Access Road Project

自动提取业主、规模、资金、项目阶段。

### Step 2：自动进入机会池

项目机会初始评分 72 分。

系统解释为什么只有 72 分：融资尚未明确。

### Step 3：发现新的融资信息

加入一条多边银行融资批准信息。

智拓识别融资状态变化。

### Step 4：重新研判

```text
融资确定性 6 → 13
总分 72 → 81
B → A
```

系统提示：

> 建议由“持续观察”升级为“重点跟踪”。

### Step 5：形成经营建议

AI生成：

- 为什么值得跟
- 当前主要风险
- 谁是关键相关方
- 公司匹配业绩
- 未来30天行动清单

### Step 6：量化效果

人工：

```text
搜索多个来源
整理资料
制作项目摘要
进行初步判断
```

AI：

```text
自动聚合 + 标准化 + 评分 + 生成研判
```

通过真实试用记录时间差。

这条故事能够完整展示：

> **发现 → 理解 → 判断 → 决策 → 行动**

而不是单点炫技。

# 20. 比赛价值指标

禁止直接写未经验证的：

> “中标率提升20%”

因为比赛周期内无法证明因果关系。

首版优先测量可真实验证指标。

## 20.1 效率指标

- 单项目信息搜集平均时间
- 单项目初步研判平均时间
- 项目摘要编制时间
- 同等时间可筛选项目数量

## 20.2 质量指标

- 项目信息字段完整率
- 关键事实证据覆盖率
- 机会发现准确率
- 重复机会合并准确率
- 人工认可的研判建议比例

## 20.3 经营过程指标

后续正式系统可跟踪：

- 机会→重点跟踪转化率
- 重点跟踪→投标转化率
- 投标→中标转化率
- 低价值项目提前退出数量
- 每个有效机会经营投入成本

# 21. 比赛评分对齐

个人赛强调真实 AI 应用价值，D 类要求可实际运行的软件系统，并提供可验证运行方式。

- 项目状态变化可触发重新研判

- 人工 vs AI 时间对比
- 市场人员实际试用评价
- 减少无效检索与材料整理

## 完整性与规范性

证明完整闭环：

```text
输入 → 发现 → 数据 → 判断 → 输出 → 行动
```

而不是孤立 demo。

## 可复用性与推广价值

智拓天然可推广：

- 不限国家
- 不限市场人员
- 不限具体工程专业
- 可扩展港口、公路、铁路、机场、市政等业务

# 27. UI设计原则

智拓不是消费互联网产品，而是企业经营决策工具。

视觉关键词：

```text
专业
国际化
沉稳
数据密度适中
地图感
决策感
```

避免：

- 大面积炫彩渐变
- AI赛博风
- 过量卡片
- 到处都是机器人图标
- 纯“大屏驾驶舱”但无法操作

产品应让人感觉：

> **这是市场负责人真的可以每天打开使用的系统。**
