# 08｜实施路线图

## 1. 总体原则

开发顺序按“先闭环、后丰富；先稳定、后扩展”。

不是先把所有页面搭出来，而是优先做通一条完整链路：

```text
导入/发现项目
→ 生成项目画像
→ 评分
→ 解释
→ 变化重评
→ 生成经营策略
```

这条链路一旦稳定，再扩展市场雷达、更多数据源和增强体验。

---

## 2. Phase 0｜项目初始化

目标：形成可持续开发基础。

任务：

- 初始化 Web 与 API 工程；
- 配置 TypeScript / Python；
- 建立 PostgreSQL；
- 创建 `.env.example`；
- 建立基础 CI；
- 建立 demo 数据目录；
- 建立统一类型/Schema；
- 完成基础开发说明。

完成定义：

- 本地一条命令可启动主要服务；
- 首页可以打开；
- API health check 正常；
- 数据库迁移正常。

---

## 3. Phase 1｜机会数据核心

目标：先有“项目机会”这个核心业务对象。

任务：

- Opportunity 数据模型；
- Organization / Country；
- Source / Evidence；
- Event；
- ScoreSnapshot；
- Demo seed 数据；
- 机会列表 API；
- 项目详情 API。

完成定义：

- 至少 10 个公开项目样本进入数据库；
- 页面可查看项目基本画像与来源。

---

## 4. Phase 2｜评分与研判核心

目标：实现智拓区别于普通市场信息平台的核心能力。

任务：

- 100 分评分规则 v1；
- 分项评分；
- 硬约束；
- 机会等级；
- 置信度；
- 评分快照；
- 分数变化计算；
- AI 评分解释；
- 缺失信息分析。

完成定义：

- 每个项目都有总分和分项；
- 每一项能显示评分依据；
- 新事实变化后能重新计算；
- 能展示 72 → 81 的变化原因。

---

## 5. Phase 3｜AI 信息理解

目标：从“人工录入 Demo 数据”升级为“AI 能理解来源并生成机会事实”。

任务：

- URL/文本导入；
- 项目识别；
- 字段抽取；
- Evidence 抽取；
- JSON Schema 校验；
- 去重匹配辅助；
- 人工确认/修正机制。

完成定义：

- 输入一段真实公开项目公告，系统可生成标准机会草稿；
- 关键字段绑定证据；
- 不确定字段标为待验证。

---

## 6. Phase 4｜经营策略

目标：回答“怎么拿”。

任务：

- AI 项目研判；
- Pursuit Thesis；
- 关键相关方；
- 竞争分析；
- 企业匹配度；
- 下一步行动清单；
- 监控触发条件。

完成定义：

- A/B 项目可以生成一份结构化、短而有用的经营策略；
- 每项建议能追溯其依赖事实；
- 不输出无依据的具体关系或虚假人物信息。

---

## 7. Phase 5｜核心 UI

目标：将能力组织成专业产品，而不是开发工具界面。

优先顺序：

1. 项目详情页；
2. 机会池；
3. 市场雷达；
4. 重点跟踪；
5. AI参谋交互。

完成定义：

- 竞赛英雄流程 3 次点击内进入核心项目；
- 项目详情一屏可看到结论、评分、风险；
- 证据、策略、变化历史可继续展开。

---

## 8. Phase 6｜持续跟踪

目标：把静态分析升级为动态经营系统。

竞赛首版可采用“模拟定时任务 + 真实公开新事件”的组合方式。

任务：

- WatchItem；
- 新来源导入；
- 变化检测；
- 重评触发；
- 事件时间线；
- 变化提示。

完成定义：

英雄项目存在两个真实或可验证时间状态，能够稳定演示：

```text
旧状态 → 新来源 → 字段变化 → 分数变化 → 策略变化
```

---

## 9. Phase 7｜竞赛验证

目标：不是“声称有效”，而是形成验证材料。

任务：

- 设计人工基准流程；
- 选择测试项目；
- 记录人工耗时；
- 记录智拓耗时；
- 统计字段准确率；
- 统计来源覆盖率；
- 收集用户试用反馈；
- 修正最明显的体验问题。

产出：

- 效率对比表；
- 准确性验证表；
- 用户反馈摘要；
- 可用于申报和答辩的真实数据。

---

## 10. Phase 8｜参赛交付

任务：

- 锁定 Demo 数据；
- 锁定英雄场景；
- 部署公开/评审访问环境；
- 演示账号；
- 演示视频；
- 使用说明；
- 系统说明；
- 申报材料；
- 答辩 PPT；
- 故障兜底方案。

完成定义：

- 新设备打开链接即可运行；
- 关键页面无明显报错；
- 3–5 分钟内完整展示主价值；
- 不依赖现场临时抓取数据才能完成演示。

## 12. 开发过程中的决策规则

遇到功能取舍时依次问：

1. 是否直接支撑“去哪里、追什么、怎么拿”？
2. 是否能增强英雄场景？
3. 是否能形成可验证业务价值？
4. 是否能在比赛时间内稳定完成？
5. 是否只是为了看起来技术复杂？

若前四项大多为否、第五项为是，则不进入竞赛首版。
