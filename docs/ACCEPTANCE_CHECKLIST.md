# 智拓赛前验收清单

本清单用于比赛提交前的产品验收。目标不是继续增加功能，而是保证核心链路稳定、可解释、可演示、可复核。

## 一、核心业务链路

- [ ] `/radar` 可正常展示市场雷达，空数据时不崩溃。
- [ ] `/discover` 可完成 URL/文本输入、项目识别、Draft 生成、重复提示。
- [ ] Draft 未经人工确认不得直接进入正式机会池。
- [ ] `/opportunities` 可展示机会评分、等级、置信度和证据。
- [ ] `/intelligence` 可演示新增证据后重评。
- [ ] `/tracking` 可展示负责人、Action、复盘与预警。
- [ ] `/strategy` 可生成策略初稿并运行红队挑战。
- [ ] `/battlecard` 可汇总形成一页式经营作战卡。

## 二、英雄项目演示

- [ ] 英雄项目 ID 固定为 `west-africa-port-access-corridor`。
- [ ] 数据库 seed 后英雄项目为 72/B 基线。
- [ ] 导入指定高等级融资与采购信息后可重评至 81/A。
- [ ] 重评必须保存 ScoreSnapshot 和 Event。
- [ ] V1/V2 策略版本可以在作战卡中体现。
- [ ] 重点行动至少 3 项，并包含负责人和优先级。
- [ ] 所有 Demo 数据均明确标识 `is_demo=true`。

## 三、AI 与防幻觉

- [ ] 未配置模型密钥时，核心 Demo 可通过 deterministic fallback 完成。
- [ ] AI 输出使用结构化 Schema，不依赖自由文本解析作为主流程。
- [ ] 不生成精确“中标概率”。
- [ ] 不无证据生成客户私人关系、领导态度、竞争对手报价。
- [ ] 信息不足时允许 `unknown / 待核实`。
- [ ] S/A 级来源 + 高置信度才允许自动触发关键评分更新。
- [ ] 低等级来源默认只进入 Evidence，不直接改变经营结论。

## 四、数据与安全

- [ ] 真实公开样例均保存来源 URL 和检索日期。
- [ ] 公开样例与脱敏 Demo 数据严格区分。
- [ ] URL 抓取禁止 localhost、内网 IP、保留地址和非标准端口。
- [ ] 网页正文大小有限制。
- [ ] 不在仓库提交 API Key、数据库密码或真实敏感经营信息。
- [ ] `.env` 已被 `.gitignore` 排除。

## 五、前端稳定性

- [ ] 数据为空时首页、雷达、机会池、策略页均有正常空状态。
- [ ] API 不可用时允许使用 Demo fallback 的页面能正常展示。
- [ ] 按钮 loading 状态明确，避免重复提交。
- [ ] 手机/窄屏布局不影响基本操作。
- [ ] 页面中不存在明显英文调试文案或开发占位符。
- [ ] 浏览器控制台无关键运行时错误。

## 六、作战卡与输出

- [ ] `/battlecard` 可打印。
- [ ] 打印时隐藏侧边栏、按钮和无关 UI。
- [ ] A4 横向排版不截断核心内容。
- [ ] 可通过浏览器打印功能保存为 PDF。
- [ ] 页面底部明确标识“AI辅助研判，不替代经营决策”。

## 七、工程质量

- [ ] `npm run check` 通过。
- [ ] `npm run build` 通过。
- [ ] `pytest -q` 通过。
- [ ] Alembic 从空数据库执行到 head 无报错。
- [ ] `zhituo-api seed` 可重复执行且不重复写入核心记录。
- [ ] `/health` 返回当前 API 版本。
- [ ] `/api/meta` 正确反映 data backend 和 AI 状态。

## 八、比赛材料

- [ ] 3–5 分钟最终演示视频脚本与实际页面一致。
- [ ] 申报表中的功能描述不超过实际实现范围。
- [ ] 所有效率提升数据均有测试或测量方法，不写虚构百分比。
- [ ] 明确说明个人独立开发部分。
- [ ] 明确说明使用的模型、开源组件和第三方公开数据来源。
- [ ] 准备“与直接使用大模型聊天的区别”答辩口径。
- [ ] 准备“如何控制幻觉/错误经营建议”答辩口径。
- [ ] 准备“如何从个人赛 Demo 推广到企业系统”答辩口径。

## 提交门槛

只有以下 5 项全部满足后，才进入正式录屏/申报：

1. 主链全通；
2. 离线/无 AI 密钥仍能演示；
3. 英雄案例结果可重复；
4. CI 或本地等价检查全部通过；
5. 演示中的所有数字都能解释来源和计算方法。
