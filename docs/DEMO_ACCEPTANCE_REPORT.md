# 中港智拓 Demo 验收报告

> 基于当前 `main` 仓库静态验收。目标：停止功能堆叠，锁定比赛主链、英雄案例和赛前整改优先级。

## 1. 结论

当前产品已经形成完整的海外市场经营闭环：

**市场雷达 → 商机发现 → 机会研判 → 情报重评 → 重点跟踪 → 赢标策略 → 红队挑战 → 一页式经营作战卡**。

产品形态已经达到“可运行比赛原型”阶段。下一阶段不建议继续增加大模块，应优先解决演示一致性、离线容错、英雄案例可重复、工程检查和量化价值证明。

## 3. 已确认的产品优势

### 3.1 不是普通大模型聊天壳

系统已经有明确业务对象和状态：Opportunity、Evidence、Score、Watchlist、Action、Alert、Strategy、Battlecard。大模型只承担抽取和推理，不承担业务事实数据库本身。

### 3.2 证据纪律已经进入产品机制

当前页面和接口已经明确区分机会评分与置信度，并允许 `unknown / 待核实`；策略页面也明确禁止在无证据时推测客户关系、竞争报价和关键人态度。

### 3.3 “去哪里—追什么—怎么拿”已经形成统一叙事

首页、雷达、跟踪、策略和作战卡之间已经形成一致经营语言，适合比赛现场快速解释，而不需要逐个介绍技术模块。

### 3.4 有现场容错基础

机会池和市场雷达已有 Demo fallback；AI 策略设计包含 deterministic fallback 思路。比赛现场应继续坚持“联网增强、离线可演示”。

## 4. 当前 P0 问题

以下问题不解决，不进入最终录屏：

1. **英雄案例必须可重复。** `west-africa-port-access-corridor` 的基线、重评结果、策略版本、行动和作战卡必须每次 seed 后一致。
2. **页面 fallback 不完全一致。** 首页/雷达可以在 API 不可用时展示 Demo，但 `/strategy`、`/tracking`、`/battlecard` 更依赖后端。正式演示环境必须保证本地 API + 数据库稳定启动，或继续补统一 Demo fallback。
3. **比赛脚本当前为 5–7 分钟，需锁定 3–5 分钟版本。** 八个页面全部逐页讲会稀释重点。
4. **需要真实工程检查结果。** 当前 CI 配置已经包含 Web `check/build` 和 API `pytest`，但赛前必须取得一次明确的全绿结果。
5. **价值量化仍需实测。** 不允许写“效率提升 80%”之类无法复核的数字；必须通过同一公开项目的人工流程与智拓流程计时形成证据。

## 5. P1 整改

1. 机会详情增加直接进入“跟踪 / 策略 / 作战卡”的连续操作入口，减少比赛现场回侧边栏寻找页面。
2. 跟踪页将 `Active Watchlist`、`priority` 等不必要英文状态统一为中文经营语言。
3. 作战卡保留 A4 横向打印，并重点检查长文本溢出。
4. 首页英雄 Demo 固定跳转英雄项目，避免数据库排序变化导致演示对象改变。
5. 现场演示所有“生成”按钮必须有 loading、失败提示和 fallback 结果。

## 6. 锁定的 4 分钟比赛故事线

### 0:00–0:30｜痛点与驾驶舱

只讲一个问题：海外经营不是缺信息，而是**信息无法快速转化为资源配置和经营行动**。

一句话定义智拓：

> 智拓把分散公开信息转化为“去哪里、追什么、怎么拿”的经营决策闭环。

### 0:30–1:05｜去哪里：市场雷达

展示市场活跃度与经营吸引力，强调二者不是同一指标。快速锁定英雄项目所在重点市场。

### 1:05–1:50｜追什么：机会研判 + 动态重评

进入英雄项目，展示：评分、置信度、Decision、证据链。随后展示一条高等级新证据进入后，项目从基线判断升级，并能解释“为什么变”。

这里是全场第一个高潮：**AI 不是写一次报告，而是持续重评经营机会。**

### 1:50–2:30｜从判断到行动：重点跟踪

展示负责人、下一次复盘、经营 Action、预警。只讲一句：

> 一个项目被判定值得追以后，系统必须继续回答“谁、什么时候、做什么”。

### 2:30–3:25｜怎么拿：赢标策略 + 红队挑战

展示赢标主张、客户诉求、差异化和证据缺口。现场只点击一次 AI：优先演示“红队挑战”。

原因：普通 AI 都会生成建议，而“主动告诉经营人员为什么可能拿不到”更能体现专业性和风险意识。

### 3:25–4:00｜作战卡收口

进入一页式作战卡，不再跳页面。用 30 秒回答：

- 值不值得追；
- 凭什么拿；
- 可能输在哪；
- 下一步谁做什么。

结束语：

> 智拓不替代市场经营人员，而是把原来分散、重复、依赖个人经验的市场经营过程，沉淀为企业可追溯、可协同、可持续学习的经营资产。

## 7. 比赛现场不演示的内容

为控制节奏，以下能力保留在产品中，但主 Demo 不主动展开：

- 批量来源扫描；
- 每一个评分维度的详细公式；
- 所有策略版本切换；
- API / 数据库技术细节；
- 长篇 AI 项目分析报告；
- 每个国家、每个专业的雷达列表。

这些内容用于评委追问，而不是占用主叙事时间。

## 8. 答辩的三个核心口径

### 与直接使用 ChatGPT/大模型有什么区别？

大模型只有一次对话；智拓有结构化机会、证据来源、评分规则、状态变化、行动责任、策略版本和组织级沉淀。模型是推理组件，经营闭环才是产品。

### AI 判断错了怎么办？

事实层使用来源等级、Evidence、置信度、Draft 人工确认和 unknown；判断层使用可解释评分；策略层增加红队挑战。最终 Go/No-Go 仍由经营人员确认。

### 企业推广价值是什么？

先减少市场人员在“搜集—整理—重复汇报”上的时间，再逐步沉淀国别、客户、项目、竞争和历史经营经验，最终形成企业级市场情报与经营决策资产。

**P0-1 英雄案例可重复 → P0-2 全链路离线稳定 → P0-3 CI 全绿 → P0-4 价值量化实验 → P1 页面连续操作与中文化 → 最终录屏。**

在 P0 完成前，不新增新的一级导航模块。
